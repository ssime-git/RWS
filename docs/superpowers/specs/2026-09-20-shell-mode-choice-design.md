# Shell mode choice: ask once per shell session

Date: 2026-09-20 · Status: approved (session decision, option B + defaults A/A)

## Problem

The v1 zsh hook always switches into `rws shell` on entering a verified mount.
The user wants to choose, at the moment of entry, whether this shell works
remotely or locally — in `cd` flows and when any terminal emulator (Ghostty,
Terminal.app, …) opens directly inside a mounted folder.

## Decision

Per-shell interactive choice, remembered for the shell's lifetime.

1. **Entry without a remembered choice** (by `cd` or shell startup inside the
   mount): prompt on the controlling TTY —
   `RWS: switch to <host> (<workspace>)? [Y/n]`.
   Enter, `y`, `Y`, `o`, `O` → remote (default). Any other key → local.
   The answer is stored per workspace in a non-exported zsh associative array.
2. **`exit` from the remote shell**: back to local zsh; no re-switch while the
   shell stays inside the volume (v1 suppression preserved).
3. **Leaving the volume and re-entering in the same shell**: the remembered
   answer is applied without asking again (remote → switch, local → stay).
4. **New shell**: memory is gone; ask again.

## Guards

- **No accessible TTY** (scripts, IDE subprocesses, agents): no prompt, no
  switch. Silent local behavior; never blocks on a prompt.
- **`RWS_AUTO_MODE=remote|local`**: forces the mode without prompting.
  Overrides remembered answers. This is the programmatic surface for future
  app/agent integration.
- **`RWS_NO_AUTO_SHELL=1`**: unchanged; disables the hook entirely.
- Context errors (unregistered volume, unverified mount): unchanged v1
  behavior — report once, suppress until the volume is left.

## Scope

Only the zsh snippet generated by `src/shell_hook.rs` changes. CLI commands,
the app and the automatic installation are untouched; the updated snippet
reaches users through the existing `.zshrc` eval line at the next shell start.

Out of scope: mode choice inside the app/Claude Desktop (prepared by
`RWS_AUTO_MODE`), bash/fish, changing one's mind mid-shell (workarounds: new
terminal or `RWS_AUTO_MODE`).

## Testing

- Rust unit tests: snippet contains the prompt contract
  (`[Y/n]`, `RWS_AUTO_MODE`, per-workspace memory).
- zsh integration tests (fake `rws`): `RWS_AUTO_MODE` both values; no-TTY
  entry stays local and silent; existing suppression/re-entry tests updated to
  force `RWS_AUTO_MODE=remote`.
- PTY tests through `script -q /dev/null`: Enter → switch; `n` → local;
  one prompt then remembered on volume re-entry.
- Live acceptance on the real mount afterwards.
